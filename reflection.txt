For this challenge, I chose to use a set and a list. The set was used to keep track of the values that had already appeared, while the list was used to store the final result in the correct order. A set worked well because it can quickly check whether a value has already been seen. If the value was not in the set, I added it to both the set and the result list. If it was already in the set, the program simply moved on to the next value. This allowed me to remove duplicates without changing the original order of the values.
The 30-minute time limit made me want to choose a solution that was simple and that I understood. Instead of trying to use a more complicated data structure, I used a set and list because I was already familiar with how they worked. This made it easier to write the code and test it within the time limit.
One trade-off with my solution is that it uses extra memory because I am storing values in both a set and a list. However, using the set makes checking for duplicates faster than repeatedly searching through the result list. I tested the program using a normal list, an empty list, and a list containing only duplicate values. All of the tests produced the expected results.
